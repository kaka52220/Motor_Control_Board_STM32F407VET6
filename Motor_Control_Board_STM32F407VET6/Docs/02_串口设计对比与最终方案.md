# 02 串口设计：我的方案与逐飞库对比，以及最终方案

> 依据：逐飞 MSPM0G3507 开源库 V3.3.4（`/workspace/review/MSPM0G3507_Library`，最新提交 `a3c9473`，2026-07-31）中的 `zf_driver_uart.c/h`、`zf_common_fifo.c/h`、`zf_common_debug.c/h`、`zf_common_interrupt.c`、`zf_device_wireless_uart.c/h`、`zf_device_type.c/h`、`seekfree_assistant*.c/h`、`project/user/src/isr.c`、`Example/Coreboard_Demo/E02_uart_demo/user/src/main.c`。逐飞库的结论都来自上面这些代码。STM32 HAL 的行为来自 ST 官方 `stm32f4xx-hal-driver`（master 分支）的 `stm32f4xx_hal_uart.c`。
> 目标场景：STM32F407，裸机轮询调度（以后迁移到 FreeRTOS）；USART1 接 USB-TTL；VOFA+ JustFloat 以 **1 kHz** 刷新，**921600 bps**；同时还要有命令行调参和日志。

## 1. 逐飞库串口是怎么做的（摘要，细节见文档 03）

| 环节 | 逐飞实现（函数/文件） | 特点 |
|---|---|---|
| 初始化 | `uart_init(uart_index, baud, tx_pin, rx_pin)`（`zf_driver_uart.c:253`）。引脚枚举里用位段编码了 UART 号、AF 号和 GPIO 号（`zf_driver_uart.h:56-121`） | 一行就能初始化，引脚写错时编译期就能发现 |
| 发送 | `uart_write_byte/buffer/string`：每个字节都 `while(DL_UART_isBusy())` 忙等，然后写入（`zf_driver_uart.c:72-114`） | **完全阻塞**，不用 DMA，也不用发送中断 |
| 接收 | 查询函数 `uart_query_byte()`、带超时的阻塞函数 `uart_read_byte()`（超时计数 `0x1FFFFF`） | 底层没有缓冲 |
| 中断 | `isr.c` 中固定的 `UARTx_IRQHandler` 按 IIDX 分发，调用 `uart_callback_list[x](event, ptr)`（`uart_set_callback` 注册），最后 `DL_UART_clearInterruptStatus(UARTx, RIS)` | 回调签名是 `void (*)(uint32 state, void *ptr)` |
| 缓冲 | 用户在回调里**每收到一个字节**调用一次 `fifo_write_buffer(&fifo, &byte, 1)`，主循环里再 `fifo_read_buffer(..., FIFO_READ_AND_CLEAN)`（E02 例程、`debug_interrupr_handler`、`wireless_uart_callback`） | 生产者在中断、消费者在主循环；软件 FIFO 默认 64 B |
| 调试输出 | `debug_init()` 把 `fputc` 重定向到 `uart_write_byte`（阻塞）；`zf_assert/zf_log` 带 `__FILE__/__LINE__` | 简单好用，但都是阻塞的 |
| 上层设备 | `wireless_uart_*`：查 RTS 流控，每 30 B 一包阻塞发送，RTS 忙时 `system_delay_ms(1)` 重试；接收通过 `set_wireless_type()` 把回调挂到全局函数指针 `wireless_module_uart_handler` | 设备层和驱动层分开 |
| 协议 | `seekfree_assistant`：帧头 0xAA（发）/0x55（收）加 8 位和校验；**收发函数通过函数指针绑定到具体通道**（`seekfree_assistant_interface_init()` 可选 debug 串口、无线串口、WiFi SPI 或自定义） | 协议层和传输通道解耦，这一点值得借鉴 |

### 读代码时发现的几个问题（可以作为面试素材）
1. **`zf_common_fifo` 并不是真正无锁的**：生产者和消费者都会改同一个 `size` 字段（写入时 `fifo->size -= 1`，读取时 `fifo->size += *length`），这两处都是读-改-写。所谓的"锁"`execution` 也是用 `|=`、`&= ~` 做非原子的读-改-写，头文件注释也承认"无法完全避免误操作"。另外，`fifo_read_buffer` 第 423 行写成了 `if((FIFO_RESET | FIFO_CLEAR | FIFO_READ) == fifo->execution)`，用的是 `==` 而不是 `&`，这个保护几乎永远不会生效。
2. **`isr.c` 每次只处理一个 IIDX，却把 RIS 全部清掉**（`DL_UART_clearInterruptStatus(UART0, UART0->CPU_INT.RIS)`）。如果 TX 和 RX 事件同时挂起，可能丢掉其中一个。
3. **同一个串口有两个消费者**：`DEBUG_UART_USE_INTERRUPT` 默认是 1（`zf_common_debug.h`），`UART0_IRQHandler` 里先调用用户回调，再调用 `debug_interrupr_handler()`。两者都会 `uart_query_byte()`，同一个字节只有一方能读到。E02 例程里用户回调也在 UART0 上，就会出现"抢字节"的问题。
4. `uart_set_interrupt_config()` 里 TX 状态位用的是 `0x10`，而枚举 `UART_INTERRUPT_STATE_TX = 0x02`，两者不一致；`ALL_ENABLE` 也不更新 `uart_interrupt_state`，之后再单独关闭 RX 会把整个 NVIC 中断关掉。
5. `seekfree_assistant_debug_param_analysis()` 里直接用 `debug_param_obj->data[channel_index - 1]`，**没有检查 `channel_index` 的范围**，收到错误帧时会越界写。我们写协议解析时一定要做范围检查。

## 2. 两种方案逐项对比

"我的方案"指上次提出的：DMA 加 IDLE 接收进环形缓冲、帧解析状态机、表驱动命令、发送队列加 DMA、日志分级、VOFA 数据和文本分开。

| 维度 | 逐飞方案（每字节中断加软件 FIFO，阻塞发送） | 我的方案（DMA 加 IDLE，环形缓冲，DMA 发送队列） | 结论 |
|---|---|---|---|
| **发送的 CPU 占用** | 阻塞发送。一个 8 通道 JustFloat 帧 36 B，921600 下要 0.39 ms，**1 kHz 时 CPU 有 39% 的时间在空转**；16 通道（68 B）时达到 74% | 只做 36 B 的 memcpy（不到 1 µs）加每块一次 TC 中断（1~2 µs），**CPU 占用小于 0.5%** | 我的方案明显更好，这是决定性差异 |
| **接收的 CPU 占用** | 每个字节一次中断。满速时每秒 9.2 万次中断，每次还要走 FIFO 的 memcpy 和状态检查 | 每条消息约 1 次 IDLE 中断，再加上每 N/2 字节一次 HT/TC 中断 | 我的方案更好（命令流量小的时候差别不大） |
| **实时性和抖动** | 阻塞发送期间主循环停住。如果在中断里打日志，中断会被拉长到几百 µs，会**破坏 1 kHz 控制节拍** | 发送异步，任何上下文写缓冲都是 O(len) 的短操作；串口中断都很短，而且优先级低于电机中断 | 我的方案更好 |
| **数据完整性** | FIFO 不是真正的 SPSC 无锁结构（共享 `size`）；溢出时 `FIFO_SPACE_NO_ENOUGH` 被调用方忽略，没有计数 | 读写指针各由一方写，单调递增；溢出、ORE/FE/NE 都有计数；发送按帧"全写或全丢" | 我的方案更好 |
| **RTOS 就绪度** | 阻塞发送会占住 CPU 直到发完（虽然更高优先级的任务仍能抢占，但同优先级和低优先级任务会被饿死）；`system_delay_ms` 直接操作 SysTick，**和 FreeRTOS 冲突** | ISR 只做"更新指针并通知"，迁移时把通知换成 `vTaskNotifyGiveFromISR` 就行 | 我的方案更好 |
| **可移植性** | 引脚枚举和 TI DriverLib 强绑定，但在逐飞自家芯片之间接口一致 | 硬件只在 `bsp_uart.c` 里出现；`ringbuf/serial/cmd/vofa` 和芯片无关，可以在 PC 上单测 | 我的方案更好，逐飞在"一套 API 覆盖多款芯片"上做得好 |
| **复杂度和上手** | 很低：`uart_init` 加一个回调就能用，十几行代码 | 中等：需要理解 DMA 环形缓冲、IDLE 和 HAL 的 RxEvent 语义、发送泵 | 逐飞更简单 |
| **可调试性** | `printf` 直接可用；阻塞发送意味着断点前的日志一定已经发出去了；assert 带文件和行号 | 异步发送时，**崩溃前最后几条日志可能还在缓冲里**，需要做"panic 时同步刷出"；有统计计数（`stat` 命令） | 各有长处，我的方案要补一个 panic flush |
| **协议层设计** | 收发函数指针让协议和通道解耦，这一点很好；但只有 8 位和校验，参数帧是定长的 | 表驱动命令，CRC16 加长度字段，ASCII 和二进制两种格式，CAN 可以复用 | 两者结合：借鉴逐飞的"传输通道函数指针" |
| **1 kHz VOFA+ @ 921600** | 能跑，但控制环要和 39%~74% 的空转抢 CPU，日志一多就掉帧或拖慢节拍 | 链路占用 39%（8 通道），CPU 几乎没有负担，有掉帧计数可以验证 | **只有我的方案能满足要求** |

**结论**：逐飞的方案适合"竞赛快速上手、串口只偶尔打印"的场景。电机控制需要 1 kHz 流式数据，同时还有 10 kHz 电流环中断，这种场景下它的阻塞发送和逐字节中断接收不能用。**最终采用我的架构**，同时吸收逐飞的 5 个优点（见 §3.10）。

## 3. 最终方案（定稿）

### 3.1 硬件与 CubeMX 配置

| 项 | 取值 | 理由 |
|---|---|---|
| 外设 | **USART1**，PA9=TX，PA10=RX（AF7） | 挂在 APB2（84 MHz）上，高波特率误差小 |
| 波特率 | **921600**，8N1，OVER16 | USARTDIV = 84e6/(16×921600) = 5.697，取 5 + 11/16 = 5.6875，实际 923077 bps，**误差 +0.16%** |
| 备选 | 2 Mbps | 84e6/(16×2e6) = 2.625 = 2 + 10/16，**误差为 0**。前提是 USB-TTL 芯片支持（CH340 和 FT232R 支持 2M，老款 CP2102 最高 921600，以芯片手册为准） |
| 不推荐 | USART2/3（APB1，42 MHz）跑 921600 | 2.848 只能取 2 + 14/16，误差 −0.93%，可以用但余量小 |
| RX DMA | DMA2 Stream2 Channel4，**Circular**，外设到内存，字节宽度，**FIFO 关闭（Direct mode）** | 循环 DMA 缓冲直接当 RX 环形缓冲用，零拷贝 |
| TX DMA | DMA2 Stream7 Channel4，**Normal**，内存到外设，字节宽度，FIFO 关闭 | 每次发送环形缓冲里的一段连续数据 |
| NVIC | USART1_IRQn、DMA2_Stream2_IRQn、DMA2_Stream7_IRQn 都设为**抢占优先级 7**（PRIORITYGROUP_4） | 见 §3.8 |
| HAL 回调 | Project Manager → Advanced → Register Callback：UART = ENABLE | `bsp_uart.c` 用 `HAL_UART_RegisterRxEventCallback()` 绑定，不去抢弱函数 |
| 内存 | DMA 缓冲**不能放进 CCM RAM（0x1000_0000）**，F407 的 DMA 访问不到 CCM | 现在工程只用了 IRAM1/IRAM2，没问题，以后做内存优化时要记住 |

### 3.3 关键数据结构与 API（只给签名，实现留给你）

```c
/* ===== Driver/ringbuf.h ===== */
typedef struct {
    uint8_t          *buf;
    uint32_t          mask;     /* size-1，size 必须是 2 的幂 */
    volatile uint32_t head;     /* 只由生产者写，单调递增，用 & mask 取下标 */
    volatile uint32_t tail;     /* 只由消费者写 */
} ringbuf_t;
void     ringbuf_init(ringbuf_t *rb, uint8_t *mem, uint32_t size_pow2);
uint32_t ringbuf_used(const ringbuf_t *rb);            /* head - tail（无符号回绕天然正确） */
uint32_t ringbuf_free(const ringbuf_t *rb);
bool     ringbuf_write_all(ringbuf_t *rb, const void *src, uint32_t len); /* 空间不够就不写，返回 false */
uint32_t ringbuf_read(ringbuf_t *rb, void *dst, uint32_t max);
uint32_t ringbuf_linear_span(const ringbuf_t *rb, const uint8_t **p);    /* 给 DMA：从 tail 起的连续可读段 */
void     ringbuf_skip(ringbuf_t *rb, uint32_t len);
```
要点：先写数据，再 `__DMB()`，最后更新 `head`；读的一方先读 `head`，再 `__DMB()`，再读数据。单核 M4 上主要防的是编译器重排，写上屏障方便以后移植。按键事件队列也用同一套思路（元素换成 2 字节，可以做一个 `evq` 的变体）。

```c
/* ===== Driver/serial.h ===== */
typedef struct {
    void     (*rx_start)(void *hw, uint8_t *dma_buf, uint16_t len); /* 启动循环 DMA 接收 */
    bool     (*tx_start)(void *hw, const uint8_t *p, uint16_t len); /* 启动一次 DMA 发送 */
    uint32_t (*lock)(void);      /* 临界区：裸机用 PRIMASK，RTOS 用 taskENTER_CRITICAL */
    void     (*unlock)(uint32_t key);
} serial_hw_ops_t;

typedef struct {
    uint32_t rx_bytes, tx_bytes;
    uint32_t rx_overflow;                 /* 消费者落后超过一整圈 */
    uint32_t tx_drop_frames, tx_drop_bytes;
    uint32_t err_ore, err_fe, err_ne, err_pe, rx_restart;
} serial_stats_t;

typedef struct {
    const serial_hw_ops_t *ops;  void *hw;
    uint8_t  *rx_dma;  uint16_t rx_len;          /* 循环 DMA 缓冲（2 的幂） */
    volatile uint16_t rx_last_pos;               /* ISR 用：上次 DMA 位置 */
    volatile uint32_t rx_wr_total;               /* ISR 写：累计收到的字节数 */
    uint32_t          rx_rd_total;               /* 消费者写 */
    ringbuf_t tx;  volatile uint16_t tx_inflight; volatile bool tx_busy;
    void (*rx_notify)(void *ctx); void *rx_notify_ctx;   /* 裸机设置标志；RTOS 发任务通知 */
    serial_stats_t st;
} serial_t;

void     serial_init(serial_t *s, const serial_hw_ops_t *ops, void *hw,
                     uint8_t *rx_dma, uint16_t rx_len, uint8_t *tx_mem, uint32_t tx_len);
uint32_t serial_read(serial_t *s, uint8_t *dst, uint32_t max);        /* 非阻塞 */
bool     serial_write(serial_t *s, const void *src, uint32_t len);    /* 非阻塞，全写或全丢 */
uint32_t serial_tx_free(const serial_t *s);
void     serial_flush_blocking(serial_t *s, uint32_t timeout_ms);     /* 仅用于 panic 或复位前 */
/* 以下由 bsp_uart.c 在 ISR 中调用 */
void     serial_on_rx_event(serial_t *s, uint16_t dma_pos);           /* HT/TC/IDLE */
void     serial_on_tx_done(serial_t *s);
void     serial_on_error(serial_t *s, uint32_t hal_error_code);
```

```c

typedef struct {
```

### 3.4 接收路径（RX）

```
PC ──► USART1 RDR ──DMA2 S2(循环)──► rx_dma[512]
                         │  HT / TC / IDLE 三种事件都会触发
                         ▼
   HAL: HAL_UARTEx_RxEventCallback(huart, Size)    // Size = 当前 DMA 写位置
                         ▼  (bsp_uart.c，优先级 7)
   serial_on_rx_event(s, Size):
       delta = (Size - rx_last_pos) & (rx_len-1);  rx_wr_total += delta;  rx_last_pos = Size;
       rx_notify(ctx)          // 裸机：g_comm_pending = 1；RTOS：vTaskNotifyGiveFromISR
                         ▼  (主循环 1 ms 任务 / CommTask)
   app_comm: n = serial_read(s, tmp, 64);  cmd_feed(tmp, n);
       serial_read: avail = rx_wr_total - rx_rd_total;
                    if (avail > rx_len) { st.rx_overflow++; rx_rd_total = rx_wr_total - rx_len/2 /*重同步*/; }
                    从 rx_dma[rx_rd_total & mask] 拷出，rx_rd_total += n
```
- 启动：`HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_dma, 512)`。DMA 设成 Circular 后，HAL 会一直接收下去，**HT、TC、IDLE 都会回调 `RxEventCallback`**，参数 `Size` 是缓冲区里的当前位置（TC 时等于 512）。HAL 源码 `UART_DMARxHalfCplt` 里传的就是 `RxXferSize/2`。可以用 `HAL_UARTEx_GetRxEventType()` 区分 HT/TC/IDLE（ST 当前的 F4 HAL 里有这个函数，请在你工程里的 `stm32f4xx_hal_uart.h` 确认）。
- **为什么能检测溢出**：HT 和 TC 保证至少每 256 字节进一次 ISR，所以 `rx_wr_total` 是精确的；消费者只要落后超过 512 字节就能检测出来，不会"悄悄地"被覆盖。
- **为什么不再额外拷进一个软件 FIFO**：循环 DMA 缓冲本身就是环，DMA 是生产者，ISR 只更新一个计数器，CPU 开销最小。

### 3.5 发送路径（TX）

```
log_printf / vofa_send / 命令应答  (main 或任务上下文)
   └─► serial_write(s, buf, len):   // 全写或全丢
          key = ops->lock();
          ok = ringbuf_write_all(&tx, buf, len);  if(!ok){ st.tx_drop_frames++; st.tx_drop_bytes += len; }
          if (!tx_busy) kick();      // kick：取连续段 → tx_busy=1, tx_inflight=n → ops->tx_start()
          ops->unlock(key);
DMA2 S7 TC → HAL_UART_TxCpltCallback → serial_on_tx_done(s):
          ringbuf_skip(&tx, tx_inflight);  tx_busy = 0;  if (ringbuf_used(&tx)) kick();
```
- **整帧原子写入**：一帧 VOFA 数据或一行日志要么完整进入缓冲，要么整帧丢弃并计数，**绝对不会出现半帧**。VOFA 解析就不会错位。
- 日志先用 `vsnprintf` 格式化到栈上的 `char line[128]`，再**一次性** `serial_write`。不要用 `fputc` 一个字符一个字符地写：那样多处输出会交错，而且每个字符都要进一次临界区。
- 临界区只包住"写缓冲加检查 busy 并启动"这几十条指令（小于 1 µs），不会影响 10 kHz 的电流环（RTOS 下用 BASEPRI 屏蔽，电流环的优先级本来就在屏蔽范围之外）。
- `printf` 可以重定向到 `serial_write`，但**禁止在任何 ISR 里调用 printf 或 log**。
- **panic 刷出**：`Error_Handler`、HardFault 和以后的 FAULT 状态里，调用 `serial_flush_blocking()`，先关 DMA，再用轮询把缓冲里剩下的数据发完，保证最后几条日志不丢。这是对逐飞"阻塞输出可靠"这一优点的补偿。

### 3.6 帧格式

**A. ASCII 命令行（第一阶段，给人用，串口助手或 VOFA+ 的命令框都能发）**
```
请求:  <name> [arg1] [arg2] ...\n      （兼容 \r\n；不超过 63 字符；参数用空格分隔；数值用 strtof 解析）
应答:  OK [data]\r\n   |   ERR <code> <reason>\r\n
日志:  [I] 123456 button: key1 double click\r\n        （级别 + ms 时间戳 + 模块）
示例:  help | ver | stat | led 1 | log 2 | stream on 8 1000 | stream off | duty 0.30
```
超长的行一直丢弃到下一个 `\n`，并且 `parse_err_len++`。

**B. 二进制帧（第二阶段，给 Python 工具用，CAN 复用同一套 CMD 编号）**
```
偏移:  0     1     2     3     4     5 … 5+LEN-1    5+LEN   6+LEN
字段:  0xA5  0x5A  LEN   CMD   SEQ   PAYLOAD        CRC_L   CRC_H
LEN = PAYLOAD 字节数（0~32）；CRC16-CCITT-FALSE（poly 0x1021，init 0xFFFF），覆盖 LEN…PAYLOAD
应答：CMD | 0x80，PAYLOAD[0] = 状态码；SEQ 原样返回（PC 端用来匹配请求和丢包重发）
```
解析状态机：`WAIT_H1 → WAIT_H2 → LEN(>32 则丢弃) → CMD → SEQ → PAYLOAD → CRC_L → CRC_H`。
- CRC 错误时**从 H1 的下一个字节开始重新找帧头**，而不是把整帧扔掉，避免漏掉嵌在里面的真帧头。
- 字节间隔超过 5 ms 就复位状态机（防止半帧把解析器卡住）。
- 自动区分格式：0xA5 > 0x7F，不可能出现在 ASCII 命令里，所以在 `WAIT_H1` 状态看到 0xA5 就走二进制分支，其余字节进行缓冲。
- 解析出来的 `CMD`、`SEQ`、参数**都要做范围检查**（对照逐飞 `channel_index - 1` 越界那个问题）。

**C. VOFA+ JustFloat（数据流，单向发送）**
```
[ch0 float32 LE][ch1]…[ch(N-1)][0x00 0x00 0x80 0x7F]       帧长 = 4N + 4
```
建议固定 ch0 = 帧计数器（float 能精确表示的整数到 2^24，1 kHz 下约 4.6 小时才回绕）。PC 端或 Python 脚本看计数器是否连续，就能**量化掉帧数**。

**文本与数据流共用一个口的规则**：一个口同一时间只有一种"主人"。
- `TEXT` 模式（默认）：日志、命令应答。
- `STREAM` 模式（`stream on` 进入）：只发 JustFloat；`log_set_mute(true)` 把 INFO 和 DBG 静默掉，只记丢弃数；命令仍然可以收，但应答只回极短的 `OK` 或者干脆不回（VOFA+ 会把夹在中间的文本当成一个坏帧，下一个帧尾就能重新同步）。
- 画 PCB 时**多预留一路串口排针**（USART2 或 USART3），后期可以一路专门发 VOFA，一路专门做日志和命令。

### 3.7 缓冲区计算

921600 bps，8N1 → 每字节 10 bit → **92.16 B/ms**，每字节 10.85 µs。

| 量 | 计算 | 取值 |
|---|---|---|
| JustFloat 8 通道帧长 | 4×8 + 4 | 36 B，占线 0.39 ms |
| 1 kHz、8 通道的链路占用 | 36 / 92.16 | **39%** |
| 1 kHz 下最多通道数（链路占用 ≤ 70%） | (0.7×92.16 − 4)/4 | ≤ 15 通道，**建议 ≤ 10** |
| RX DMA 环 | 命令行 ≤ 64 B、二进制帧 ≤ 39 B；comm 任务 1 ms 一次，满速时每次积压 ≤ 92 B；512 B 能扛住主循环被阻塞 **5.5 ms** | **512 B** |
| TX 环 | 排空速度 92 B/ms；1 kHz 流占 36 B/ms，剩 56 B/ms 给日志；`help` 一次突发约 1 KB，约 18 ms 排完；2 KB 能缓冲 **22 ms** | **2048 B** |
| 一帧 VOFA 的最坏排队延迟 | 2048 / 92.16 | 22 ms（正常小于 1 ms） |
| 日志行缓冲（栈上） | 一行 ≤ 128 B | 128 B |
| 栈 | vsnprintf 带 %f 时约 0.5~1 KB | 启动文件栈改为 0x1000 |

RAM 合计约 2.7 KB，F407 有 192 KB，完全不是问题。

### 3.8 中断优先级规划（NVIC_PRIORITYGROUP_4，数字越小优先级越高）

| 抢占优先级 | 中断源 | 说明 |
|---|---|---|
| 0 | TIM1_BRK_TIM9 | 硬件过流刹车。PWM 已经由硬件关断，ISR 只锁存故障码 |
| 1 | ADC（JEOC，注入组完成） | **10 kHz 电流环**，不调用任何 RTOS API，执行时间目标小于 20 µs |
| 2~4 | 预留（编码器 Z 相、输入捕获） | 同样不调用 RTOS API |
| — | **configMAX_SYSCALL_INTERRUPT_PRIORITY = 5** | 分界线：5 及以下（数字 ≥ 5）的中断才能调用 `xxxFromISR` |
| 5 | 1 kHz 控制节拍定时器 | 通知 ControlTask（裸机阶段直接在 ISR 里跑速度环、位置环） |
| 6 | CAN1_RX0 / SCE | |
| **7** | **USART1、DMA2_Stream2（RX）、DMA2_Stream7（TX）** | 都很短（小于 5 µs）；有 HT 加 512 B 缓冲，容忍 2.7 ms 的响应延迟 |
| 8~14 | 其它（按键扫描用的 1 ms 定时器等） | |
| 15 | SysTick / PendSV（FreeRTOS 内核）；HAL 时基 TIM6 | 上 RTOS 前 SysTick 就是 HAL 时基 |

原则：**串口永远不能打断电流环**。现在裸机阶段就按这张表配，上 FreeRTOS 时数字一个都不用改。

### 3.9 错误处理

| 错误 | 来源 | 处理 |
|---|---|---|
| ORE（溢出）、FE（帧错误）、NE（噪声）、PE（校验） | `HAL_UART_ErrorCallback` 读 `huart->ErrorCode` | 对应计数加 1。**DMA 接收模式下，HAL 会把任何一种错误都当成阻塞错误：结束接收，并 Abort RX DMA**（`HAL_UART_IRQHandler` 里 `if (ORE || dmarequest) { UART_EndRxTransfer(); HAL_DMA_Abort_IT(); }`）。所以必须在 ErrorCallback 里**重新调用 `HAL_UARTEx_ReceiveToIdle_DMA()`**，同时 `rx_restart++`、`rx_last_pos = 0`，否则串口会"静默死掉"，这是最常见的坑 |
| 软件 RX 溢出 | `serial_read` 检测到 `avail > rx_len` | `rx_overflow++`，重新同步，记一条 WARN |
| TX 缓冲满 | `serial_write` 返回 false | 整帧丢弃，`tx_drop_frames++`；VOFA 掉帧可以在 ch0 计数器上看出来 |
| 帧错误 | 解析器 | `parse_err_crc / parse_err_len / unknown_cmd / bad_arg` 计数；ASCII 回 `ERR code` |
| DMA FIFO 错误（FEIF） | F4 DMA | 用 Direct mode 并关掉 FIFO 就不会出现；HAL 在 FE 时只记录、不终止，可以忽略 |
| 线路断开或拔插 | 一般表现为 FE 或噪声 | 通过上面的重启机制自动恢复 |

`stat` 命令把 `serial_stats_t` 和解析器计数全部打印出来，论文的"通信测试"表可以直接引用。

### 3.10 吸收逐飞库的优点

1. **传输通道函数指针**（`seekfree_assistant_interface_init`）对应我们的 `serial_hw_ops_t` 加 `cmd_init(table, n, reply_port)`：协议和通道解耦，CAN 也能接进来。
2. **`zf_assert / zf_log` 带 `__FILE__/__LINE__`**：我们做 `ASSERT(x)`，失败时进入 `panic(file, line)`。
3. **assert 时把输出置于安全状态**（逐飞 `debug_protective_handler()` 的思路是"断言后防止信号维持导致硬件失控"，它的实现被注释掉了）：我们在 panic 里**第一件事就是关 PWM 主输出（清 TIM1 的 MOE）**，然后才打日志。电机控制必须这么做。
4. **统一的函数头注释模板**（函数简介/参数说明/返回参数/使用示例/备注信息）。
5. **回调统一成 `(event, void *ptr)` 形式**：你的按键已经这么做了，串口的 `rx_notify(ctx)` 保持一致。

不借鉴的部分：阻塞发送、逐字节中断接收、共享 `size` 的 FIFO、计数器式开关中断、直接操作 SysTick 的延时、`zf_common_headfile.h` 这种"一个头文件包含全部"的做法、自定义 `uint8` 类型（直接用 `<stdint.h>`）。

### 3.11 迁移到 FreeRTOS 时的对应关系

| 裸机（现在） | FreeRTOS（以后） | 需要改的地方 |
|---|---|---|
| `rx_notify` 设置 `volatile g_comm_pending` | `vTaskNotifyGiveFromISR(comm_task, &woken); portYIELD_FROM_ISR(woken);` | 只改 `app_comm.c` 里注册的那个回调 |
| 调度表 1 ms 调一次 `comm_poll()` | `CommTask`：`ulTaskNotifyTake(pdTRUE, pdMS_TO_TICKS(10))` 后 `comm_poll()` | 函数体不变 |
| `ops->lock` 用 PRIMASK | `taskENTER_CRITICAL()`（BASEPRI，不屏蔽优先级 0~4） | 只改 `bsp_irq.h` |
| `vofa_send` 在 1 kHz 节拍里调 | 在 `ControlTask` 末尾调，或者交给 `LogTask` 用队列发快照 | 不变 |
| 多个写者（日志、应答、VOFA） | 依旧靠 `serial_write` 内部的临界区保证整帧原子 | 不变 |
| HAL 时基 SysTick | TIM6 | CubeMX |
| `printf` | 只允许在任务里用；`CommTask` 栈 ≥ 512 word | — |
