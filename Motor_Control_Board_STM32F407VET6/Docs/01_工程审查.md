## 1. 分层与目录结构

### 1.1【必改】确定目录结构，依赖只能向下

现状：只有 `BSP/inc/Button.h`、`BSP/src/Button.c`，按键**驱动**被放在了 BSP 目录里；业务逻辑（`keycontext`、生产者/消费者回调）写在 `Core/Src/main.c:57-100`。

建议的目录（以后串口、电机都按这个放）：

```
Motor_Control_Board_STM32F407VET6/
├─ Core/                 CubeMX 生成，只在 USER CODE 区里写 1~2 行调用
├─ Drivers/              HAL/CMSIS，不动
├─ BSP/                  本板相关：引脚映射、外设句柄、HAL 回调转发
│   ├─ bsp.h / bsp.c          bsp_init()，统一初始化入口
│   ├─ bsp_led.h / .c         LED（处理低电平点亮）
│   ├─ bsp_key.h / .c         按键电平读取（引脚表）
│   └─ bsp_uart.h / .c        USART1+DMA 的 HAL 胶水层（下一步）
├─ Driver/               与芯片无关，只依赖 <stdint.h> 和函数指针
│   ├─ button.h / .c          现在的 Button.c 挪过来
│   ├─ ringbuf.h / .c         通用 SPSC 环形缓冲（串口、按键事件共用）
│   └─ serial.h / .c          串口收发引擎（下一步）
├─ Middleware/           与硬件无关、可以在 PC 上单测
│   ├─ log.h / .c   cmd.h / .c   vofa.h / .c
└─ App/                  业务：调度器、按键事件处理、命令表
    ├─ app.h / app.c          app_init()、app_loop()
    ├─ app_sched.c            轮询调度表
    └─ app_key.c              按键事件的消费者
```

规则（写进 README，面试时讲）：
1. `App → Middleware → Driver → BSP → HAL`，**只允许上层 include 下层**。
2. Driver 和 Middleware 里禁止出现 `#include "main.h"`、`gpio.h`、`stm32f4xx_hal.h`、`GPIOx`、`HAL_xxx`。验收办法：`grep -rn "HAL_\|GPIO\|main.h" Driver Middleware` 结果为空。
3. 下层通知上层只用**回调（函数指针加 `void *ctx`）或队列**。
4. `main.c` 只保留 CubeMX 代码，加上 `USER CODE BEGIN 2` 里的 `app_init();` 和 `while(1)` 里的 `app_loop();`。这样 CubeMX 重新生成代码时不会冲掉业务，换 PCB 时也只改 BSP。

### 1.2【必改】`Button.h:3` include 了 `gpio.h`，驱动依赖了 HAL

`gpio.h → main.h → stm32f4xx_hal.h`，于是整个 HAL 被拖进了通用驱动。`Button.h` 实际只需要 `<stdint.h>`（以及 NULL 用到的 `<stddef.h>`）。

### 1.3【必改】`Button.c:6-17` 的 `read_button_gpio()` 写死了板级引脚

这是上次审查提过的问题，**还没改**。`KEY1_GPIO_Port/KEY1_Pin`、`KEY2_...` 属于板级知识，应该放到 `BSP/bsp_key.c`，做成表驱动：

```c
/* bsp_key.h —— 只暴露逻辑接口 */
typedef enum { BSP_KEY1 = 0, BSP_KEY2, BSP_KEY_NUM } bsp_key_id_t;
uint8_t bsp_key_read_level(uint8_t key_id);      /* 返回物理电平 0/1，签名与 button 的读函数指针一致 */
```
`bsp_key.c` 内部用 `static const struct { GPIO_TypeDef *port; uint16_t pin; } s_key_map[BSP_KEY_NUM]` 查表，越界返回空闲电平。`Button.h:53` 里 `read_button_gpio` 的声明一并删掉。

### 1.4【必改】LED 没有 BSP 接口（上次提过，这次一起处理）

现状：`.ioc` 配了 `PB8 = LED16_low`（推挽输出），`gpio.c:55` 上电时写 `GPIO_PIN_RESET`，但工程里没有任何 LED 代码。将来 App 要么直接调用 `HAL_GPIO_WritePin(LED16_low_GPIO_Port, ...)`，要么自己记"低电平点亮"，两种都会把板级细节泄漏到上层。

```c
/* bsp_led.h */
typedef enum { BSP_LED_RUN = 0, BSP_LED_NUM } bsp_led_id_t;
void bsp_led_set(bsp_led_id_t id, bool on);      /* on=亮；低电平有效在 BSP 内部处理 */
void bsp_led_toggle(bsp_led_id_t id);
```
- 引脚表里多加一个 `active_low` 字段，上层只关心"亮/灭"。
- 再往上可以在 Driver 层加一个 `led_pattern`（非阻塞闪烁：心跳 1 Hz、故障码闪 N 次），在 App 里用来显示 `READY/RUN/FAULT`，第 6 个里程碑会用到。
- 注意 `gpio.c:55` 上电输出低电平。由于 LED 是低电平点亮（看名字是 `_low`），**上电时 LED 是亮的**。如果这不是你想要的，在 CubeMX 里把 PB8 的 GPIO output level 改成 High（不要改 gpio.c，重新生成会被覆盖）。

## 2. 按键驱动 `Button.c / Button.h`

### 2.0 已修复项确认 ✅
- `Button.c:107-120`：PRESS 状态松手后进 `BTN_STATE_RELEASE`，`ticks > LONG_TICKS` 时触发 `LONG_PRESS_START` 并进入 `LONG_HOLD`。上次的两个 bug 都修好了。
- `Button.c:122-147`：RELEASE 状态超时后按 `repeat` 次数区分单击/双击，逻辑正确。
- `button_attach()` 现在可以设置 `user_data`（`Button.c:65`）。

### 2.1【必改】在回调里调用 `button_stop()` 会打断遍历（`Button.c:249-258` 和 `:223-246`）
`button_Task()` 先执行 `button_handle(target)`，再读 `target->next`。如果某个回调里调用了 `button_stop(target)`（比如"长按后停用这个按键"），`:239` 会把 `handle->next = NULL`，**本轮后面的按键全部跳过**。
修法：遍历时先保存 `next`：`button *next = target->next; button_handle(target); target = next;`。这是链表加回调的经典重入问题，面试里很好讲。

### 2.2【建议】`button_attach()` 只有一个 `user_data`，后注册的会覆盖前面的（`Button.c:57-66`）
`cb[]` 是按事件区分的数组，`user_data` 却只有一个，所以 `button_attach(&btn1, EVT_A, f, ctxA); button_attach(&btn1, EVT_B, g, ctxB);` 之后，`f` 收到的也是 `ctxB`。二选一：
- 改成 `void *user_data[BTN_EVENT_COUNT]`；或者
- 保持"每个按键一个上下文"的语义，把它从 attach 里拿出来，单独提供 `button_set_user_data()`，并在头文件注释里写明。
（main.c 现在每个按键只用了一个 ctx，所以暂时没出错。）

### 2.3【建议】`LONG_HOLD` 每 5 ms 触发一次（`Button.c:173-177`），接上队列后会刷爆
每秒 200 个事件。改成事件队列之后，16 深的队列 80 ms 就满了。加一个 `BTN_HOLD_REPEAT_TICKS`（例如 100 ms / 5 ms = 20），在 LONG_HOLD 状态里按这个周期触发，复用 `ticks` 计数即可。

### 2.4【建议】边界比较不一致（`Button.c:154` 和 `:164`）
REPEAT 状态下 `ticks < SHORT_TICKS` 时回到 RELEASE，`ticks > SHORT_TICKS` 时进 PRESS，**正好等于 `SHORT_TICKS` 时松手会直接回 IDLE，这次连击被吞掉，什么事件都不发**。统一写成 `<` 和 `>=`。

### 2.5【可选】其他行为细节
- 连击 3 次及以上时，`:136-143` 什么事件都不发。可以加一个 `BTN_MULTI_CLICK`，或者提供 `button_get_repeat(handle)`，让上层读取次数。
- REPEAT 转 PRESS（第二次按住不放）时 `ticks` 清零，所以这种情况下要按 `SHORT+LONG ≈ 1.3 s` 才进长按。确认这是你想要的行为，并写进注释。
- `button_init` 里 `memset` 之后又逐个赋 0（`:25-27`），可以删掉多余的赋值。

### 2.6【建议】命名与头文件规范
| 现状 | 问题 | 建议 |
|---|---|---|
| `Button.c / Button.h` | 只有这个文件大写开头 | `button.c / button.h` |
| `typedef struct button button;` | 类型名和 struct tag、变量名混在一起 | `typedef struct button button_t;` |
| `buttonState`、`buttonEvent`、`BtnCallBack` | 驼峰、缩写混用 | `button_state_t`、`button_event_t`、`button_cb_t` |
| `button_Task` | 大小写混用 | `button_scan()`（它其实是"扫描一步"） |
| `static void button_handle()` | 和 `handle` 指针同名，语义不清 | `button_fsm_step()` |
| `DEBOUNCE_TICKS`、`TICKS_INTERVAL`、`SHORT_TICKS` | 没有模块前缀，容易和别的模块冲突 | `BTN_DEBOUNCE_TICKS`、`BTN_SCAN_PERIOD_MS`… |
| `#ifndef __BUTTON_H__` | C 标准保留了以双下划线开头的标识符 | `#ifndef BUTTON_H` |
| `#include "string.h"`（`Button.c:2`） | 标准头用了引号 | `#include <string.h>` |

| `button_stop` | 实际做的是"从链表移除"，不是暂停 | `button_unregister()`，和 `button_register()` 成对 |

### 2.7【建议】注释风格
`Button.c:11、:19、:24、:237` 这些是**学习笔记**（"这里注意 break 是否需要…"、运算符优先级）。建议挪到 `docs/notes.md`。代码注释只写**为什么这样做**，函数头统一用一个模板（可以参考逐飞的"函数简介/参数说明/返回参数/使用示例/备注信息"，见文档 03）。`Button.c:259-275` 末尾有 17 行空行，删掉。

### 2.8【建议】ISR 上下文的说明
以后 `button_Task()` 要放进 1 ms 定时器中断时，有两点要写进头文件注释：
1. **回调会在中断上下文里执行**，回调里只能做入队，不能 printf，也不能调用阻塞函数。
2. `button_register/unregister` 在 main 里改链表、ISR 在遍历链表时：单核 Cortex-M4 上，现有的写法（先写 `handle->next`，再写 `head`；摘除时一次性写 `*curr`）每一步都是单字写，ISR 看到的链表总是一致的，**现在是安全的**。但这是"碰巧安全"，要在注释里说明。上 FreeRTOS 后用 `taskENTER_CRITICAL()` 包住修改链表的代码。

## 3. `Core/Src/main.c`

### 3.1【必改】`main.c:57-100` 的 `keycontext` 计数器：一旦生产者进了 ISR 就会丢事件
`ctx->long_start_pending++`（生产者）和 `ctx->long_start_pending--`（消费者）是对**同一个变量**的读-改-写（编译后是 LDR/ADD/STR 三条指令）。按我们的计划把扫描挪进 1 ms 中断以后，如果 main 正在执行 `pending--` 时被中断打断，ISR 里的 `++` 就会被覆盖，**事件丢失**。现在两者都在 main 里，所以测不出来。
正确做法（也就是下一步要做的）：
- 用 **SPSC 环形队列**：`head` 只由生产者写，`tail` 只由消费者写，不需要关中断（详见文档 02 的 `ringbuf`，元素是 `{uint8_t id; uint8_t evt;}`）；或者
- 用"两个单调计数器"：生产者只 `produced++`，消费者只 `consumed++`，用 `produced - consumed` 得到待处理数。
另外，`long_start_handled` 加 `volatile` 没有意义，可以去掉。

### 3.2【必改】`main.c:65-66` 的 `volatile int a, b;`
这是调试用的全局变量，用来接 `button_enroll` 的返回值。删掉，改成检查返回值，失败时进 `Error_Handler()` 或者记日志。

### 3.3【建议】业务逻辑从 main.c 挪到 `App/`
`main.c:57-100、:134-156` 全部挪到 `App/app_key.c` 和 `App/app.c`。main.c 只留：
```c
/* USER CODE BEGIN 2 */  app_init();   /* USER CODE END 2 */
/* USER CODE BEGIN 3 */  app_loop();   /* USER CODE END 3 */
```
另外，CubeMX 的 `USER CODE BEGIN WHILE` 和 `USER CODE BEGIN 3` 之间夹着 `/* USER CODE END WHILE */`。你现在把代码放在 WHILE 段（`:150-156`），可以用，但统一放 `BEGIN 3` 更规范。

### 3.4【建议】调度逻辑：魔法数和"追赶"行为（`main.c:143-156`）
- `5` 和 `Button.h:6` 的 `TICKS_INTERVAL` 重复了，两处必须一起改，属于隐患。
- `button_tick_last = 0`，但执行到这里时 `HAL_GetTick()` 已经是几十 ms 了，所以第一次进循环会连续执行多次 `button_Task()` 来"追赶"。另外 `+= 5` 的写法意味着主循环被阻塞 100 ms 后会**连续跑 20 次**。对按键来说问题不大，但对 1 kHz 的控制和日志任务来说，这种突发是不希望出现的。
- 建议做成**调度表**，并且明确策略：
```c
typedef struct { void (*fn)(void); uint16_t period_ms; uint32_t last; uint32_t max_us; } sched_task_t;
```
  初始化时 `last = HAL_GetTick()`；如果落后超过一个周期，就**跳过追赶**（`last = now`），同时把 `overrun++` 计数，用 `stat` 命令打印出来。`max_us` 用 DWT->CYCCNT 统计每个任务最长的执行时间。这是面试时证明"系统有余量"的数据，以后迁移到 RTOS 时可以对照。

### 3.5【可选】只挂了长按回调
单击和双击还没有挂回调，所以没法从外部验证 §2 的修复。串口跑通以后，第一个验收项就是"每种事件打印一行日志"。

## 4. 中断与并发（为串口做准备）

### 4.1 `stm32f4xx_it.c` 现状
只有 CubeMX 默认的异常处理和 `SysTick_Handler → HAL_IncTick()`（`:183-191`），没有用户代码，这是对的。之后**不要在 `stm32f4xx_it.c` 里写业务**：串口的 `USART1_IRQHandler` 和 `DMA2_StreamX_IRQHandler` 保持 CubeMX 生成的 `HAL_xxx_IRQHandler()` 调用，用户逻辑全部通过 HAL 回调进入 `bsp_uart.c`。

### 4.2【建议】启用 HAL 回调注册
`Core/Inc/stm32f4xx_hal_conf.h:193` 中 `USE_HAL_UART_REGISTER_CALLBACKS 0U`。建议在 CubeMX 的 Project Manager → Advanced Settings → Register Callback 里把 UART 设为 ENABLE，然后在 `bsp_uart.c` 里用 `HAL_UART_RegisterRxEventCallback()` 绑定。这样可以避免多个模块争着重写同一个弱函数 `HAL_UARTEx_RxEventCallback`。如果不开也可以，那就只在 `bsp_uart.c` 里重写弱函数，用 `huart->Instance` 分发。

### 4.3【建议】临界区工具
在 `BSP/` 里提供一对工具，**保存和恢复 PRIMASK**，而不是用"计数器嵌套"（逐飞的 `interrupt_global_disable` 用的是计数器，见文档 03 §5.4）：
```c
static inline uint32_t bsp_irq_save(void)    { uint32_t p = __get_PRIMASK(); __disable_irq(); return p; }
static inline void     bsp_irq_restore(uint32_t p) { __set_PRIMASK(p); }
```
上 RTOS 后，这对函数的内部实现换成 `taskENTER_CRITICAL()/EXIT`（或者用 BASEPRI 只屏蔽 ≤ configMAX_SYSCALL 优先级的中断，这样电流环中断不会被屏蔽），上层代码不用改。

## 5. CubeMX `.ioc` 与时钟、NVIC 配置

| # | 项 | 现状（`.ioc` 原文） | 严重度 | 建议 |
|---|---|---|---|---|
| 5.1 | 中断优先级分组 | `NVIC.PriorityGroup=NVIC_PRIORITYGROUP_2` | **【必改】** | 改成 **`NVIC_PRIORITYGROUP_4`**（4 位全部用作抢占优先级，0~15，没有子优先级）。FreeRTOS 要求这样设置（官方 Cortex-M 移植说明）；现在改了，以后串口和电机中断的优先级数字就不用重排。 |
| 5.2 | 48 MHz 时钟域 | `PLLQ=4` → `RCC.48MHZClocksFreq_Value=84000000` | 【建议】 | USB OTG FS、SDIO、RNG 要求 48 MHz（SDIO 要求 ≤48 MHz）。现在没用到，但改成 `PLLQ=7` 就是正好 48 MHz，没有任何代价，免得以后用 RNG 或 USB 时踩坑。 |
| 5.3 | 系统时钟 | HSE 8 MHz，M=4，N=168，P=2 → 168 MHz；APB1=42 MHz，APB2=84 MHz；FLASH 5WS | ✅ | 正确。VCO 输入 2 MHz，符合 ST 推荐值（抖动最低）。请对照开发板原理图确认晶振确实是 8 MHz。`uvprojx` 里的 `CLOCK(25000000)` 只影响软件仿真器，可以忽略。 |
| 5.4 | LSE | 占用了 PC14/PC15，但 `SystemClock_Config` 没有开启 LSE | 【可选】 | 不用 RTC 的话就在 CubeMX 里关掉，把引脚释放出来。 |
| 5.5 | HAL 时基 | SysTick（`VP_SYS_VS_Systick`），`TICK_INT_PRIORITY 15` | 【建议，上 RTOS 时】 | 上 FreeRTOS 时，CubeMX 的 SYS → Timebase Source 改成 **TIM6 或 TIM7**，SysTick 留给 RTOS。逐飞库的 `system_delay_ms` 直接操作 SysTick，正好是反面教材（见文档 03）。 |
| 5.6 | 按键上下拉 | `PA0` 和 `PE8` 都是 `GPIO_NOPULL`，main 里两个按键的有效电平都是 1 | 【必改：核实】 | 确认开发板上这两个按键**有外部下拉电阻**（很多板子上 PA0/WK_UP 有，PE8 不一定有）。如果没有，引脚就是悬空的，会误触发。没有外部下拉的话就在 CubeMX 里配成 Pull-down。 |
| 5.7 | 栈和堆 | `StackSize=0x400`，`HeapSize=0x200` | **【必改，写串口之前】** | 加上 `vsnprintf`（尤其是 `%f`）、日志缓冲和命令解析以后，1 KB 栈很容易溢出。在 CubeMX 里改成 **0x1000**（4 KB；F407 有 128+64 KB RAM，完全够用），堆可以保持不变，因为不用 malloc。一定要在 `.ioc` 里改，直接改 `startup_stm32f407xx.s` 会被重新生成覆盖。 |
| 5.8 | 串口 | 还没配置 | 下一步 | 按文档 02 §4.1 配置 USART1 PA9/PA10，921600 bps，DMA2 Stream2 做 RX（Circular），Stream7 做 TX（Normal）。 |
| 5.9 | 调试接口 | `SYS_JTMS-SWDIO / SWCLK` | ✅ | 正确，PB3/PB4/PA15 没有被 JTAG 占用。 |

## 6. 编码、格式与工程文件

### 6.1【必改】源码编码统一成 UTF-8
用工具检测：`BSP/src/Button.c`、`BSP/inc/Button.h`、`Core/Src/main.c` **不是合法的 UTF-8，是 GBK**；`README.md` 和 `.gitignore` 是 UTF-8。后果是 GitHub 网页、VS Code 和 AI 工具看到的中文注释全是乱码（我审查时也得先用 iconv 转码），以后还可能和 UTF-8 文件混在一起。
- 做法：Keil → Edit → Configuration → Editor → Encoding 选 **UTF-8 without signature**。已有的文件用 VS Code 的 "Reopen with Encoding: GBK" 打开，再 "Save with Encoding: UTF-8"，或者用 `iconv -f GBK -t UTF-8`。转换完单独提交一次，提交信息写 `chore: convert sources to UTF-8`，不要和功能改动混在一起。
- AC5 编译中文**注释**没有问题。字符串字面量里尽量不要写中文，日志一律用英文。
- 再加一个 `.gitattributes`：
  ```
  * text=auto
  *.c text eol=lf
  *.h text eol=lf
  *.s text eol=lf
  *.uvprojx text eol=crlf
  *.uvoptx  text eol=crlf
  *.ioc     text eol=lf
  ```
  （现在 `Button.c` 是 LF 换行，保持 LF 就行。）

### 6.2【建议】统一代码格式
`Button.c` 里大括号相对函数名多缩进了一级（Whitesmiths 风格），`main.c` 的 CubeMX 部分是 K&R 风格，tab 和空格也混着用（比如 `main.c:134-135` 的缩进对不齐）。建议在仓库根目录放一个 `.clang-format`，让 VS Code 或命令行一键格式化：
```yaml
BasedOnStyle: LLVM
IndentWidth: 4
UseTab: Never
BreakBeforeBraces: Allman
ColumnLimit: 120
AlignConsecutiveMacros: true
AlignConsecutiveDeclarations: true
```
CubeMX 生成的文件不要格式化（会影响 USER CODE 区的合并），只格式化 `BSP/ Driver/ Middleware/ App/`。

### 6.3 MDK 工程 `MDK-ARM/*.uvprojx`
| 项 | 现状 | 严重度 | 建议 |
|---|---|---|---|
| 编译器 | `pCCUsed = V5.06 update 7`，`uAC6=0`（ARMCC 5） | 【建议】 | AC5 已经被 Arm 停止维护，建议切到 **AC6（armclang）**，C99 或 gnu11。切换后注意 printf 重定向的写法（AC6 用 `__asm(".global __use_no_semihosting")`，或者直接勾选 MicroLib）。 |
| 优化等级 | `<Optim>4</Optim>`（AC5 下对应 -O3，以 Keil 界面显示为准） | 【建议】 | 开发和调试阶段用 **-O1**（AC6 下用 `-O1` 或 `-Og`）。-O3 下变量常被优化掉，单步跳来跳去，调 PI 时很痛苦。Release 再开 -O2 或 -O3，并对比 ISR 的执行时间。 |
| 包含路径 | `IncludePath` 里有 `../BSP/src` | 【建议】 | 源文件目录不应该放进包含路径。重构后改成 `../BSP;../Driver;../Middleware;../App`（或者每层一个 `inc`）。 |
| 分组 | `BSP/src`、`BSP/inc` 两个组（头文件也加进了组） | 【建议】 | 按层分组：`App`、`Middleware`、`Driver`、`BSP`、`Core`、`HAL`。头文件不用加进组。 |
| C99 | `uC99=1` | ✅ | 保持开启（支持混合声明和 `//` 注释）。 |
| 警告 | `wLevel=2`（All Warnings） | ✅ | 保持。目标是 **0 warning**，把 warning 当 error 对待。 |
| FPU | `RvdsVP=2`（单精度 FPU） | ✅ | PI 用 `float` 时性能足够。注意常量要写 `1.0f`，避免被提升成 double 走软件运算。 |
| uvoptx | 已入库 | 【可选】 | 里面是断点和窗口布局，团队协作时噪声较大。单人项目入库也可以。 |
